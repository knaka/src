# “Mise” — tool version and task manager

mise manages project-local tool versions and runs tasks. Tool versions are listed in `.mise.toml` and `.mise/conf.d/*.toml`.

mise can be invoked without a global installation using the bootstrap scripts: `./mise` on Linux and macOS, or `.\mise.cmd` on Windows.

````bash
# install all tools
./mise install

# execute a project-locally-installed command
./mise exec -- jq --help

# list available tasks
./mise tasks

# run task `foo`
./mise run foo

# show a task `foo`'s full description and the path of the file that defines it
./mise tasks foo
````

## File layout

Files for mise work behind the scenes, so they are dotfiles that `ls` does not show. Only the bootstrap scripts, which users type, are visible.

| Path | Role |
|---|---|
| `./mise`, `.\mise.cmd` | Bootstrap scripts |
| `.mise.toml` | Main configuration: settings, environment variables, and tool versions |
| `.mise-tasks.sh`, `.mise-tasks.bash` | The project's main function tasks |
| `.mise/conf.d/*.toml` | Shared configuration, read together with `.mise.toml` |
| `.mise/tasks-*.sh`, `.mise/tasks-*.bash` | Shared function tasks |
| `.mise/tasks/` | File tasks: one executable file per task |
| `.mise/conf.d/_function-task-bindings.toml` | Generated by the `funcs:bind` task. Do not edit |

Project-specific files go at the top of the project. Files shared across tasks or projects go under `.mise/`. Subprojects such as `go/` and `js/` follow the same layout in their own directories.

## Function tasks

A function task is a task defined as a shell function in a file that holds several of them, such as `.mise-tasks.{sh,bash}` or `.mise/tasks-*.{sh,bash}`.

* A function named `task_<name>` defines the task `<name>`. `__` in the function name becomes `:` in the task name, so `task_docker__start` defines `docker:start`.
* The comment line directly above the function becomes the task's description.
* `#MISE` lines above the function add task settings, such as `#MISE tools={"uv"="0.10"}`.

mise does not read these files directly. The `funcs:bind` task generates `.mise/conf.d/_function-task-bindings.toml`, which defines one TOML task per function that sources the file and calls the function. After adding, removing, or renaming a function task, or changing its comment or `#MISE` lines, run `funcs:bind` in that project's directory and commit the regenerated file.

````bash
./mise run funcs:bind
````

If the generated file is broken and mise cannot load its configuration, run the script directly, without mise, to regenerate it.

````bash
sh .mise/tasks/funcs/bind.sh
````

# Testing

All tests are executed via the `test` task.

````bash-session
$ mise run test
[test] $ # .mise/tasks-test.sh:task_test
Test "octdump"@tests-bindump.sh Passed
Test "hexdump"@tests-bindump.sh Passed
...
````

To run specific tests, specify their names.

````bash-session
$ mise run test hexdump string_length
[test] $ # .mise/tasks-test.sh:task_test
Test "hexdump"@tests-bindump.sh Passed
Test "string_length"@tests-string.sh Passed
````

Tests are implemented following these conventions:

* Placing a `test_foo` function inside a `.lib-test/tests-*.{sh,bash}` script makes the test `foo` available.
* Placing a shell script named `.lib-test/test_bar.{sh,bash}` makes the test `bar` available.
* `.lib/*.{sh,bash}` are scripts that implement functionality, but placing a `test_baz` function inside one makes the test `baz` available.

# Shell Script Grammar

Shell script files with the `.bash` extension must be implemented using only features available up through Bash version 3, since they need to run under Bash version 3 on macOS.

Files with the `.sh` extension should generally be implemented using only POSIX shell features, so that they are executable with Bash POSIX mode, Dash, and BusyBox Ash. However, `local` variable declarations are not part of POSIX shell features, but they can be used as they are available in the shells listed above.

Special shell variables like `$IFS` can be overridden with `local` declarations. Shell scoping is dynamic, not lexical, so this override remains in effect for the function itself and for any functions it calls (until they return) — but it still does not affect the outer scope, i.e. the code that called the function where it was declared.

# MSYS2 commands in Mise environment on Windows

On Windows, `mise install` installs a base MSYS2 environment (the `http:msys2` tool defined in `.mise/conf.d/msys2.toml`) and adds its `msys64/usr/bin` to `PATH`, giving access to standard UNIXy commands (bash, coreutils, sed, grep, awk, perl, tar, curl, ...). This tool is Windows-only; on Linux and macOS these commands come from the system instead.

The `postinstall` step additionally installs `bc`, `diffutils`, and `patch`, so the installed package set is narrower than a full MSYS2 install.

Known-missing commands from the POSIX command set (noticed absent, not currently installed): `ed`, `gcc` (so no `c99`), `m4`, `make`, `vim` (and no `vi`). Don't assume these exist on Windows without checking first.
